## 方針

- まずは個別コマンドより先に、CLIの共通基盤を実装する
- PDF処理は`qpdf`を外部コマンドとして利用する
- ユーザー向け仕様は`docs/command-spec.md`を基準とする
- 実装者向けの判断はこの文書内の「実装前提」を基準とする
- 実装優先順は `merge` → `remove` → `reorder` → `rotate` → `insert` → `replace` → `split` を基本とする

## 実装前提

### 共通方針

- `qpdf` の検出優先順は `--qpdf` → `NATA_QPDF` → `PATH`
- CLI引数エラーは `Cli::try_parse()` で受ける
- `--help` と `--version` は終了コード `0`
- それ以外の不正引数は終了コード `1`

### ページ指定

- ページ指定は「文字列 → 中間表現 → 総ページ数で実ページ列へ解決」の2段構成
- 共通パーサは広めに受ける
- `odd` / `even` の禁止、単一ページ要求、空結果禁止は後段バリデーションで掛ける
- ページ列は順序維持、重複許可、1始まりを前提にする

### 入出力

- 入出力共通基盤は単一出力コマンドを先に対象にしている
- 正式出力は一時ファイル経由で確定する
- 成功時のみ正式パスへ移動し、失敗時は途中生成物を正式出力として残さない

### `extract` 実装方針

- `extract` は最初の縦切り実装とする
- 入力PDFの総ページ数は `qpdf --show-npages` で取得する
- ページ抽出は `qpdf <input> --pages . <range> -- <output>` を使う
- `extract` では `odd` / `even` を許可する
- `extract` では空結果禁止、単一ページ限定なしとする

### 横断的な未実装

- `merge` 以降の他サブコマンド本体
- `render` コマンド本体
- PDFページ数取得以外のPDF情報取得
- `qpdf` 実行本体の高度な抽象化
- 暗号化PDFの本格対応
